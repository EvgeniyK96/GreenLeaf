Как читать:
- Цель «Lighthouse mobile ≥ 85 с 3D» **выполняется в штатном режиме** (медиана 90): 3D есть на странице, но three.js не мешает первому экрану и откликам.
- Если заставить three.js грузиться сразу внутри замера (`eager`), выходит 75: инициализация WebGL и разбор 740 КБ three.js на этом CPU стоят ~0,9 с блокировки. Асинхронная компиляция шейдеров (`KHR_parallel_shader_compile`) этим GPU не поддерживается, поэтому дальше ужать нельзя без отказа от three.js.
- First screen < 2,5 с: FCP/LCP 0,8–1,3 с во всех мобильных сценариях с аппаратным GPU.

Режимы для ручной проверки: `?3d=on` (включить 3D), `?3d=low` (облегчённая сцена), `?3d=eager` (on + сразу после load), `?3d=off` (только постер).

## 4. Браузер: ширины и режимы

| Ширина | 3D (`?3d=on`, движение мыши/касание) | Без 3D (`prefers-reduced-motion: reduce`) | Горизонтальный скролл |
|---|---|---|---|
| 360 | канвас hero появляется через ~0,35 с после взаимодействия | постер, 0 канвасов | нет |
| 768 | то же | постер | нет |
| 1280 | то же; «рост» в блоке начислений — второй канвас, грузится за 600 px до блока | постер + SVG-стебель | нет |

- Без взаимодействия 3D появляется через ~3,3 с после загрузки.
- Канвасов на странице не больше 2 (лимит 3). Вне экрана рендер на паузе (`frameloop="never"`), «рост» рисует кадр только при скролле (`demand`).
- На телефонах «рост» не грузится: вместо него текстовые группы; карточки пакетов наклоняются в 3D только при мыши.
- Без JS: весь текст, FAQ, пакеты и форма видны (пререндер).
- Скриншоты: `content/qa/*.webp`.

## 6. Дефекты, найденные и исправленные

1. Основной чанк статически тянул r3f/React из-за группировки чанков → React вынесен в свою группу, `includeDependenciesRecursively: false`.
2. Проба WebGL при монтировании блокировала поток на секунды в headless → дешёвые проверки сразу, проба — после load и простоя, с `failIfMajorPerformanceCaveat`.
3. LCP «прыгал» 0,8 ↔ 3,3 с: модульный скрипт иногда выполнялся до первой отрисовки → скрипт подключается после первого кадра (с `modulepreload`).
4. LCP ждал анимацию прозрачности подзаголовка → анимируются только кнопки и факты.
5. Долгая гидрация всей страницы → ленивая гидрация блоков при подходе к экрану (`Island`), форма гидрируется сразу по клику на любую CTA.
6. Ложная ошибка контраста из-за `content-visibility` на тёмном блоке → `content-visibility` только у светлых блоков.
7. Кнопка «Открыть план (PDF)» была невидимой (лайм на лайме) → правило цвета ссылок не трогает кнопки.
8. «Перспектива» наезжала на текст на десктопе; лишняя пустота у «Трёх путей»; длинные слова в ценниках на 360 px; 6 карточек пакетов на телефоне → лента с прокруткой.
9. Листья в hero «белели» от бликов → материал Lambert; сцена сдвинута правее текста.
10. В dev гидрация срабатывала на HTML-комментарий → проверка `firstElementChild`.
11. `robots.txt` отсутствовал (SEO 91 → 100).
12. Пустой блок «Или напишите напрямую» в продакшене → скрывается, если контактов нет.

## 6а. Повторная проверка 09.11.2026 (жалоба «анимация не работает»)

Причины, найдены при просмотре страницы как обычный посетитель (без `?3d=`):

1. **На ноутбуке с 2 ядрами 3D не включалось вообще.** Правило «≤ 2 ядер → постер» срабатывало на AMD Athlon 3050U с нормальной видеокартой Radeon. Теперь постер только при ≤ 1 ядре или ≤ 1 ГБ памяти; 2–4 ядра получают облегчённую сцену, а программный рендер и отсутствие WebGL по-прежнему отсекает проба WebGL.
2. **В `npm run dev` сцена падала с `504 Outdated Optimize Dep`.** Vite не видел three.js/r3f при старте (они подключаются только ленивым импортом) и пересобирал зависимости на лету. Добавлено `optimizeDeps.include` в `vite.config.ts`. На продакшен-сборку это не влияло.
3. Firefox: проба WebGL читает `RENDERER` вместо устаревшего в Firefox `WEBGL_debug_renderer_info`.

Проверено после исправления (dev и продакшен, без параметров, 1280 px, движение мыши):

| Браузер | Канвас hero | Движение листьев (доля изменившихся пикселей за 1 с) | «Рост» в блоке начислений | Ошибки в консоли |
|---|---|---|---|---|
| Firefox 1572 (Playwright) | ✅ | 11,1% | ✅ (2 канваса) | нет |
| Chromium 1254, аппаратный GPU | ✅ | 11,2% | ✅ (2 канваса) | нет |

Lighthouse mobile в авторежиме после исправления: 85 / 84 (three.js по-прежнему грузится после взаимодействия, в замер не попадает).

Побочный эффект проверки: установка Playwright Firefox удалила из `~/.cache/ms-playwright` неиспользуемый Chromium 1247; вместо него установлен Chromium 1254, остальные браузеры не тронуты.

## 7. Не проверено / ограничения

- Реальные iOS/Android-устройства и Safari — нет доступа; нужна проверка на 2–3 телефонах клиента.
- Деплой на Vercel не выполнялся (нужен аккаунт клиента и решение по приёму заявок, см. `COMPLIANCE.md`).
- Устройства с ≤ 1 ядром или ≤ 1 ГБ памяти, без аппаратного WebGL, в режиме экономии трафика и на 2G получают постер — это сознательное решение.
- CLS 0,022 — сдвиг подзаголовка при подмене шрифта (в зоне «хорошо» < 0,1).
- Высота страницы до прокрутки — оценочная (`content-visibility`), полоса прокрутки может слегка подстраиваться.
